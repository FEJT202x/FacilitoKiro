# Specification v1.0 — DICOM MRI Viewer

**Status:** Active
**Date:** 2026-08-22

## Scope

Version 1 delivers a **DICOM-based 2D MRI viewer** for prostate cancer imaging.
MRI scans are clinical DICOM data, so the viewer works with real DICOM files
from the start — not JPEG/PNG placeholders.

## Client Requirement

The client has explicitly requested **DICOM support from the first version**.
Prostate MRI studies are multi-slice DICOM series with clinical metadata,
pixel spacing, and window/level information that must be preserved.

## Functional Scope (v1)

- Load DICOM files and full series from local storage (drag & drop / file picker)
- Parse DICOM P10 and common transfer syntaxes
- Render slices with correct window/level (VOI LUT) in grayscale
- Scroll/stack navigation through slices of a series
- Zoom, pan, and window/level (WW/WC) tools
- Display DICOM metadata (patient, study, series, sequence)
- Switch between MRI sequences within a study

## Out of Scope (deferred to later versions)

- Multi-planar reconstruction (v2)
- Segmentation overlays (v3)
- DICOMweb / PACS server integration (v4)
- Annotations, measurements, reporting (v5)

## Technology Decision

| Concern | Choice | Rationale |
|---------|--------|-----------|
| Rendering engine | **Cornerstone3D** | De-facto standard for web medical imaging; WebGL GPU rendering; powers OHIF |
| DICOM parsing | `@cornerstonejs/dicom-image-loader` + `dicom-parser` | Robust P10 parsing; integrates natively with Cornerstone3D |
| UI framework | Vue 3 (Composition API) + TypeScript + Vite | Modern, typed, fast dev loop; team familiarity |
| State | Pinia | Viewport & UI state management |
| Styling | Tailwind CSS | Rapid medical UI development |
| Testing | Vitest + Vue Test Utils | Unit and component tests |

**Note:** Cornerstone3D is framework-agnostic (renders to DOM/canvas), so it
integrates cleanly with Vue 3.

**Rejected:** Canvas API with JPEG/PNG — inadequate for clinical DICOM data.
**Rejected:** dwv — lighter but Cornerstone3D scales further without a rewrite.

## Acceptance Criteria

- [ ] Load real DICOM files/series from local storage
- [ ] Slices render with correct window/level and grayscale
- [ ] Smooth slice scrolling through a full series
- [ ] Zoom, pan, and window/level tools function correctly
- [ ] DICOM metadata is displayed
- [ ] Clear error on malformed/unsupported DICOM
- [ ] Large series (hundreds of slices) load without freezing

## Privacy Note

In v1, all patient data stays client-side. No images are uploaded to any server.
